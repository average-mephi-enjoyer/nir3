# Методика экспериментов НИР3

**Дополнительное условие приёмки пользователя:** без реального локального LLM-прогона
эксперимент не принимается. Результаты предыдущей серии с heuristic имеют статус
предварительного контроля. Развёртывание описано в `docs/local_llm_setup.md`;
текущий CLI по умолчанию требует local_llm, а эвристика включается явно.

## Область проверяемого утверждения

Прототип исследует загрязнение адаптивного эталона и компромисс между адаптацией,
обнаружением и доступностью мониторинга. Числовая синтетика не подтверждает качество
психолингвистических признаков или LLM. Наличие архитектуры само по себе не доказывает
научную новизну. Итоговые числа генерируются из запусков, а не задаются в документации.

## Данные и время

CERT r4.2: исходные файлы доступны только локально и не изменяются. `email.csv` должен
быть хронологическим; одинаковые timestamp обрабатываются в исходном порядке строк.
Неупорядоченный поток отклоняется, а не сортируется с неявной потерей идентичности.
События телеметрии могут поступать в любом порядке; запрос выбирает `[t-W,t]` и стабильно
сортирует по времени. Исходная временная зона CERT не указана: к наивным часам
прикрепляется UTC исключительно для одинаковой арифметики. Это не утверждение о
географическом часовом поясе организации; преобразования DST не выполняются.

`insiders.csv` и подробные observables — источники разметки. Observables имеют переменную
ширину: первые четыре поля — тип, ID, время, пользователь. Ключи событий разных журналов
могут совпадать; интерпретировать ID следует вместе с типом источника. Все сценарии
пользователя сохраняются. Письмо из подробной разметки получает 1; неразмеченное письмо
в интервале любого сценария — −1; вне сценариев — 0 согласно полноте доступного answer
key, а не независимой экспертной оценке. Первое размеченное техническое действие не
объявляется доказанной эксфильтрацией. Источник и качество меток сохраняются в выгрузке.

Согласно локальному `r4.2/readme.txt`, содержимое писем — синтетические ключевые слова,
не полноценные тексты; `file.csv` представляет копирование на съёмный носитель.
Отсутствие поля activity не отменяет документированную семантику выпуска. Само
копирование не доказывает неправомерность. В данных намеренно завышена концентрация
инсайдерских сценариев и встречаются пропуски событий.

## Разделение и роли

Синтетика: 60 ежедневных наблюдений train, 74 calibration, затем 180 test. Разделы
генератора `tune` и `test` используют независимые семейства seeds 1000+ и 10000+.
Тест не участвует в выборе параметров. Подбор — предзаданный one-at-a-time набор вокруг
базовой конфигурации для Protected. Потеря: пропуск сценария + доля загрязнения + число
ложных эпизодов + доля недоступности. Пропуск и загрязнение учитываются только там,
где определены. Это предпочтение исследовательского протокола, не универсальная функция
стоимости. Выбор фиксируется в `selected_parameters.json` до итоговых прогонов.

CERT: от первого пригодного письма 30 суток train, следующие 30 calibration; test
начинается на 74-е сутки. Между calibration и test остаётся 14-дневный разрыв; он не
используется для подбора порогов. Сценарии с началом до test явно сохраняются как
`not_evaluable`, с причиной недостаточной подтверждённой предыстории. Они не исчезают
из знаменателя перечня доступных сценариев. Это фиксированное разделение, а не
реализованное сценарно-зависимое обучение.

`--all-users` выбирает всех пользователей answer key r4.2 и дополнительно до двух
сотрудников каждой роли по хешу seed+ID. Этот отбор не исключает заранее известных
инсайдеров: метки применяются только при оценке. Пять кандидатов ролевого prior на роль
выбираются отдельным seed без знания будущих исходов. Целевой сотрудник исключается
при построении собственного prior; нужны минимум два других сотрудника с наблюдениями.
Неизвестная/малочисленная роль означает индивидуальный режим, а не смесь случайных ролей.
При наблюдаемой смене LDAP-роли устанавливается независимый prior новой роли, если
он был оценён на train; иначе prior отключается. Якорь не меняется вслед за LDAP.
Сравнение оценивает мониторинг одного сотрудника во времени. Независимость обучающей
и тестовой популяций для переноса между сотрудниками НЕ заявляется: референтные
сотрудники разных тестовых пользователей могут пересекаться.

## Признаки и пропуски

| Маркер | Определение / единица | Недоступность |
|---|---|---|
| pronoun | I/(I+we+1), безразмерный | пустой текст не используется парсером |
| syntactic | эвристика длины и пунктуации, [0.10,0.85] | не называется разбором spaCy |
| activity | min(1, abs(изменение числа исходящих за сутки)/3) | нет двух полных суток истории |
| response | std приближённого времени ответа /24 часа, [0.05,0.95] | нет минимум двух сопоставленных ответов; в CERT нет тем |
| social | смесь обратной лог-связности и доли внешних адресов | без графового контекста |
| пять semantic | авторские категории, [0,1] | disabled, пустой текст, недостаточный контекст LLM |

Недельная, месячная и квартальная динамика требуют соответственно 14, 60 и 180 суток
календарной истории. Они сохраняются в контексте; риск использует суточный маркер.
Для каждого метода применяется одна маска доступности; в абляции явно исключаются
группы признаков. Если в train у признака меньше двух доступных измерений и нет prior,
он не включается в нормировку. Пропуск не равен измеренному нулю. Betweenness не
подменяется долей внешних связей; массовый бенчмарк не вычисляет неиспользуемую
betweenness. Граф локален наблюдаемым коммуникациям сотрудника, не всей организации.
Пользователи сопоставляются точно, с явными алиасами; подстроки ID не используются.

## Риск, профиль и контекст

Для доступных обученных признаков M: `z_j = clip((x_j-mu_j)/(sigma_j*c_j), -10, 10)`,
`R = sqrt(sum(z_j²)/|M|)`. Параметры train — выборочное среднее и дисперсия с ddof=1,
нижняя граница дисперсии 1e−4. Риск рассчитывается до обновления. Локальный риск и
отклонение текущего наблюдения от исторического якоря сохраняются раздельно;
якорь ограничивает обновления, но не меняет формулу детектора в эксперименте A.

При ролевом prior: `eta = n_j/(n_j+tau)`, смешанное среднее `eta*mu+(1-eta)*mu_role`,
дисперсия `eta*v+(1-eta)*v_role+eta*(1-eta)*(mu-mu_role)²`. Число n_j учитывает
доступность конкретного признака. Несовместимые ролевые распределения не объединяются.

EMA: `mu' = mu+alpha*(x-mu)`; `v' = max(v_min,(1-alpha)*(v+alpha*(x-mu)²))`.
Для якоря до изменения эталона проверяются оба ограничения:
`abs(mu'_j-anchor_mu_j)/sqrt(anchor_v_j) <= anchor_limit` и
`v'_j/anchor_v_j <= anchor_variance_ratio`. Ограничения среднего и дисперсии независимы.
Отклонённое обновление не меняет эталон. Истинные метки не поступают в эти решения.

Нагрузка коллег оценивается по завершённым календарным дням с лагом в сутки: 7 дней
против предыдущих 23. Целевой сотрудник исключён. Нужны минимум два коллеги с полной
30-дневной предысторией и активностью в обоих интервалах. Используется общий состав
сравнимых коллег; исчезновение группы не повышает порог. Фактор `w=clip((rate_ratio-1)/2,0,1)`.
Только синтаксический, ответный, alienation и conflict маркеры получают `c=1+0.5*w`.
Concealment и access не смягчаются; общие пороги от дедлайна не повышаются.

## Карантин и заморозка

Для кандидата сохраняются ID, время, исходный риск, действовавший порог h, R/h,
максимум нормированного риска наблюдаемого горизонта и история переходов. Через D суток
критерий допуска — максимум R_t/h_t строго меньше 1. Каждое новое наблюдение использует
свой действующий порог; старые решения не пересчитываются. Решение не может использовать
события после его времени. Дубликаты ID и обратный ход часов отклоняются.

`PENDING → ADMITTED/REJECTED`; `ADMITTED → REVOKED` при откате. ADMITTED после проверки
карантина ещё не означает включение в эталон: оно отдельно фиксируется после проверки
якоря. Поле `included_in_reference` и журнал переходов устраняют эту неоднозначность.

Последовательная тревога переводит связку профиль/детектор через
`ACTIVE → ALERT_PENDING_REVIEW → FROZEN`. Эти два перехода при тревоге выполняются
атомарно для вызывающего конвейера; pending не является ожиданием пользовательского UI.
Недавние EMA-обновления откатываются с восстановлением среднего, дисперсии и счётчиков;
кандидаты горизонта отклоняются. Детектор не создаёт новые тревоги до решения проверки.
`RESUMING → ACTIVE` требует явного approved, проверенной обучающей выборки и независимой
калибровки. Исторический якорь сохраняется; автоматического «прощения по метке» нет.
Проверенная новая выборка заменяет прежний эталон, поэтому прежние включённые обновления
помечаются REVOKED с причиной замены. Некорректная выборка не меняет замороженный профиль:
проверка и обучение нового эталона выполняются до изменения действующего состояния.
В CERT внешние решения проверки отсутствуют, поэтому заморозка сохраняется до конца
наблюдения и снижает доступность. Это существенное ограничение метода, а не скрытый успех.
В синтетическом false_alert_then_attack проверка предписана на 15-й день до запуска;
используется независимо заданная обучающая предыстория. Запланированные проверки
применяются при ближайшем наблюдении; время между событием проверки и наблюдением
остаётся временем недоступности.

## Последовательный детектор

По умолчанию эмпирическое правило 3 из 5 и регистрация начал эпизодов. Порог —
квантиль независимой фиксированной calibration; оценки не фильтруются по малому риску.
Тестовые оценки никогда не добавляются в calibration. Недостаточно длинная калибровка
отклоняется. При изменении распределения исходная калибровка может стать невалидной;
чистота CERT calibration не является доказанным свойством реальной организации.

Экспериментальный режим: `p=(1+#calibration>=score)/(N+1)`, `e=beta*p^(beta-1)`;
накапливается сумма log(e). Условие `E[e_t | F_(t-1)] <= 1` для адаптивных зависимых
потоков НЕ доказано. Rank p-values не объявляются условно валидными. Гарантия Вилле,
заданный anytime FPR и контроль множественного тестирования сотрудников не заявляются.
Представленные итоговые серии используют k-of-n; e-process требует отдельного исследования
зависимости, остановки и множественного контроля. Наблюдаемая частота тревог не является
универсальной вероятностной гарантией.

## Эксперименты A и B

A: Static, EMA, EMA clipped (R < 2h_alert/3), EMA quarantine, EMA quarantine + anchor,
Protected (дополнительно заморозка с откатом). У всех один поток, маски, индивидуальная
инициализация, правило риска, контекст (выключен) и calibration. Изменяется управление
обновлением/состоянием профиля. Пороги при одинаковой инициализации совпадают.
Тест с выключенными различиями требует одинаковых траекторий всех методов.

B: базовые; базовые+граф; базовые+граф+семантика; полный без контекста; полный с
контекстом; полный с ролью; без карантина; без якоря; без заморозки. В текущем прототипе
«базовые+граф+семантика» и «полный без контекста» намеренно совпадают — это контроль
эквивалентности, а не два независимых улучшения. Вариант технической верификации не
включён: качество не проверено независимо. Результаты A и B сохраняются отдельно.

Grid A: (30,3), (90,1), (90,3), (90,6), (360,0.5) — длительность в сутках и амплитуда
в исходных sigma. B использует (90,3). Скорость записывается отдельно как amplitude/days;
для скачка это номинальная конфигурация, а не фактическая длительность фронта.
`ema_proxy_drift` назван согласно генератору: это не противник, видящий защищённый детектор.
Смена роли меняет значения и независимый prior, коллективный stress меняет активность
коллег, burnout — только целевого сотрудника. Very_slow использует тот же линейный закон,
что ramp; именно условие (360, 0.5) задаёт горизонт длиннее теста и крайне низкую скорость.
Остальные настройки этой категории являются контрольными скоростями, а не все «очень медленными».
Дополнительно проверяются нормальный поток и ложная тревога до атаки.

## Метрики и интервалы

Загрязнение ever = 100 * число положительных тестовых ID, когда-либо включённых /
число положительных ID. Retained исключает отозванные обновления; отдельно показано
число отзывов. ID не заменяется совпадением timestamp/вектора. Доля блокировок штатных
обновлений — число нормальных карантинных решений, отклонённых якорем / все завершённые
нормальные карантинные решения; незавершённые кандидаты исключены. Она не равна доле
всех сообщений, заблокированных любой защитой.

Oracle только синтетический: EMA на контролируемой чистой траектории с тем же alpha.
Ошибка среднего — RMS в единицах oracle sigma; ошибка дисперсии — RMS относительной
ошибки v/oracle_v−1. Доброкачественные изменения входят в чистую траекторию. Для CERT
oracle отсутствует; выводится N/A. Отклонение от начального якоря — отдельная величина,
не ошибка относительно неизвестной истинной нормы.

AP корректно обрабатывает равные scores; −1 исключены. Recall@1%FPR — описательная
тестовая ROC-метрика, не рабочая гарантия. При отсутствии положительных примеров — N/A.
После заморозки score для мониторинга недоступен. AP/Recall рассчитываются только
по доступным scores и могут выглядеть лучше при ранней остановке, поэтому их нельзя
интерпретировать без доли обнаруженных сценариев и доступности. Доля обнаруженных
сценариев включает пропущенные во время заморозки как 0. Задержка и упреждение определены
только при тревоге в интервале сценария; упреждение относительно размеченного действия
может быть отрицательным. Неопределённые значения сопровождаются na_reasons.

Экспозиция — прошедшие календарные сутки между началом теста и концом наблюдения,
включая дни без писем. Для normal user-days исключается объединение интервалов сценариев.
В синтетике конец — сутки после последнего наблюдения; CERT — конец общего наблюдаемого
потока плюс одна секунда. Активные пользователь-дни показаны отдельно. Числитель FA —
начала эпизодов с известной нормальной меткой вне сценариев. Неизвестные метки не
превращаются в нормальные. Заморозка измеряется календарным временем; её доля и число
ложных остановок сохраняются отдельно. Текущая экспозиция не моделирует увольнения как
окончание мониторинга; это ограничение для интерпретации частоты CERT.

Для каждого условия 30 независимых seeds. Это даёт исследовательские интервалы,
но не гарантирует узких границ редких ошибок: при доле 0.5 стандартная ошибка около
0.091. Bootstrap 2000 повторений, фиксированный seed. При агрегации настроек сначала
усредняются результаты одного seed; затем ресемплируются seed-кластеры. Коррелированные
письма не считаются независимыми испытаниями. Синтетические bootstrap-интервалы не
переносятся на реальную популяцию работников. Полный факторный подбор и анализ
взаимодействий гиперпараметров не выполнены.

## Семантика и техническая верификация

Режимы: heuristic (лексические эвристики), local_llm (локальный OpenAI-compatible
сервер Qwen), disabled. Скрытого fallback нет. Разрешены только буквальные loopback IP;
proxy окружения и redirects отключены. В эксперименте режим сохраняется в каждом
векторе. LLM confidence — внутренняя некалиброванная оценка, не вероятность правильности.
Evidence проверяется на точную подстроку; сохраняются ID сообщения, Python Unicode
offsets [start,end), хеш фрагмента и альтернативное объяснение. Исходные цитаты не
дублируются в отчётах. Пять категорий — авторские, не оригинальная шкала ILI.
Схема и клиент проверяются mock-тестами; это не доказательство устойчивости самой LLM
к prompt injection. Результат проверки реального сервера — `output/local_llm_probe.json`.

Телеметрия различает available/missing/not_loaded/incomplete. В основном CERT запуске
загружаются file/device/logon; HTTP 14 ГБ явно not_loaded. Разрешённые категории ресурсов
должны поступать из независимой матрицы полномочий; LDAP role не равен разрешению на
все файлы категории. Без такой матрицы и сопоставимого семантического контекста статус
NOT_COMPARABLE. USB+файл не становится CRITICAL_EXFILTRATION. CONFIRMED_VIOLATION требует
явного независимого подтверждения и источника; парсер CERT сам его не создаёт.
