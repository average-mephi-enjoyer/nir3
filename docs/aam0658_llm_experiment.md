# Реальный LLM-эксперимент: aam0658, 12.11.2026

Полный проход завершён: Qwen2.5-7B-Instruct Q4_K_M обработала 629 исходных писем CERT локально через llama.cpp. Сравнение проведено на одинаковых 506 тестовых письмах. Улучшения обнаружения сценария при добавлении LLM в этом прогоне не получено.

| Подход | Сценарий обнаружен | Ложные эпизоды тревоги | Допущено обновлений эталона | Заморозки |
|---|---:|---:|---:|---:|
| Qwen + защищённый динамический профиль | Нет | 0 | 117 | 0 |
| Защищённый динамический профиль без LLM | Нет | 0 | 35 | 0 |
| Обычная EMA без LLM | Нет | 0 | 506 | 0 |

LLM изменила траекторию риска и отбор обновлений, но большее число обновлений само по себе не означает лучшую точность или устойчивость. Вариант без LLM полностью исключает пять семантических признаков; словарная эвристика не используется.

## Протокол и ограничения

- Обучение: 59 писем до 01.02.2010 07:11:45; калибровка: 64 письма до 03.03.2010 07:11:45; тест: 506 писем начиная с 17.03.2010 07:11:45. Промежуточные 30 писем используются только для контекста. Все границы совпадают с предыдущим прогоном.
- Протокол A: alpha EMA = 0.05; карантин = 14 дней; ограничения дрейфа и дисперсии относительно исходного эталона, заморозка и откат — у защищённых вариантов. Порог каждого подхода определяется 99-м процентилем его независимой калибровки. Последовательное правило тревоги одинаково.
- Ролевые эталоны, поправка на командную нагрузку и conformal выключены во всех трёх вариантах. Это сравнение защищённого профиля в протоколе A, а не проверка всех возможных конфигураций. Другие сценарии через LLM не обрабатывались.
- Интервал сценария: 23–29 октября 2010 года. В answer key нет положительных email-событий для aam0658: в тесте 494 наблюдения имеют метку 0, ещё 12 внутри интервала сценария — неизвестную метку −1. Поэтому PR-AUC, Recall@FPR и загрязнение положительными письмами — N/A; задержка и опережение обнаружения также N/A, поскольку тревоги не было.
- По документации CERT `email.content` — список ключевых слов, а не полноценное письмо. Результат не доказывает психолингвистическую точность или переносимость на реальные рабочие переписки.
- Значение доступности мониторинга 1.0 означает отсутствие заморозки алгоритма. Оно не означает непрерывного наличия писем: календарная экспозиция в прежнем протоколе заканчивается вместе со всем архивом, а не с последним письмом aam0658.
- Техническая верификация по тревоге не инициировалась: ни один подход не сформировал тревог. Качество технического подтверждения этим экспериментом не оценено.

## Реальное покрытие LLM

Выполнено 638 HTTP-запросов для 629 писем, включая 9 повторных запросов после ошибок валидации. LLM-этап занял 3832,41 секунды (63 мин 52 с), без учёта подготовки общих признаков. Повторное использование кэша в этом прогоне: 0.

Валидных результатов — 614; невалидных — 15: 7 ответов с числом выше допустимой границы 1, 2 с неточной цитатой, 6 обрезанных по лимиту генерации. Невалидные результаты помечены как недоступная семантика, без эвристической подмены. В обучении пропусков нет; в калибровке их 2, в тесте — 13. Таким образом, семантика доступна для 493 из 506 тестовых писем.

Ненулевые семантические признаки получены для 15 писем всего, из них 10 в тесте. Это ответы модели, а не подтверждённые вредоносные письма.

## Что было проведено раньше

`output/single_cert` и `output/final_cert` использовали словарную эвристику (`semantic_mode=heuristic`). В прежнем протоколе A защищённый профиль дал 0 тревог и допустил 3 обновления; EMA дала 3 ложных эпизода, не обнаружила сценарий и допустила 506 обновлений. Эти старые строки нельзя обозначать как полностью отключённую семантику. Новые варианты без LLM пересчитаны отдельно.
