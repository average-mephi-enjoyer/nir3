# Локальная Qwen для НИР3

Подготовлен portable-вариант для этого компьютера: Intel i5-12500H, 16 ГБ RAM,
встроенная Iris Xe. Qwen2.5-7B-Instruct Q4_K_M работает через CPU-сборку llama.cpp.
Наличие LLM необходимо по условию пользователя, но само по себе не доказывает качество
маркеров и научную валидность результатов. Прежние эвристические таблицы предварительные.

## Что подготовлено и что ещё не выполнено

Файлы конфигурации, загрузки, проверки SHA256, запуска, остановки и интеграции созданы.
Веса и portable executable установлены пользователем; 12.11.2026 проверены SHA256,
alias работающего сервера и три реальных запроса. Результат —
`output/local_llm_probe.json`. Это проверка интеграции, а не завершённый эксперимент CERT.

Зафиксированы:

- модель `Qwen/Qwen2.5-7B-Instruct-GGUF`, ревизия `bb5d59e06d9551d752d08b292a50eb208b07ab1f`;
- два официальных Q4_K_M GGUF-шарда, вместе 4 683 073 632 байт (4,68 ГБ);
- CPU runtime `llama.cpp b12317`, Windows x64 ZIP 25 084 543 байт;
- SHA256 всех трёх загрузок в `configs/local_llm.json`, полученные из официальных метаданных;
- 6 потоков генерации, 8 batch threads, контекст 4096, одна параллельная последовательность;
- endpoint `http://127.0.0.1:8081/v1/chat/completions`, alias `nir3-qwen2.5-7b-instruct-q4_k_m`;
- temperature=0, фиксированный seed, max_tokens=768, timeout=600 секунд.

Все артефакты находятся в `<проект>/local_llm/`, исключённом из Git. Модель не сливается
в дополнительный файл: llama.cpp получает первый шард и читает остальные рядом.
Ни служба Windows, ни PATH, ни драйверы, ни системная политика PowerShell не изменяются.
При отсутствии системной DLL или блокировке политики остановитесь и передайте ошибку;
скрипты не устанавливают runtime-пакеты администратора и не меняют политику сами.

## Действия пользователя

Загрузка 4,71 ГБ и запуск нагружающей CPU модели оставлены пользователю согласно его
указанию о существенных действиях. Во время проверки было свободно около 5,3 GiB RAM.
Перед запуском закройте ненужные приложения: скрипт требует минимум 7 GiB свободной RAM,
желательно 8–10 GiB. Это консервативная проверка, не гарантия отсутствия нехватки памяти.
На диске перед установкой требуется не менее 7 GiB свободного места.

Откройте обычный PowerShell, без прав администратора:

```powershell
Set-Location C:\__study\nir\3_sem\prot_2
.\scripts\setup_local_llm.ps1
.\scripts\setup_local_llm.ps1 -Download
.\scripts\start_local_llm.ps1
uv run python scripts/probe_local_llm.py
```

Первый вызов показывает план без загрузки. `-Download` скачивает только указанные
версии с GitHub/Hugging Face, поддерживает продолжение `.part`, проверяет размер и
SHA256 до распаковки. Несовпавший файл не исполняется и не удаляется автоматически.
Повторный запуск переиспользует прошедшие проверку файлы. Не используйте installer
Ollama или глобальную установку через winget для этой конфигурации.

Запуск повторно хеширует веса и runtime, проверяет RAM и свободный порт, затем
создаёт скрытый фоновый процесс. Сервер слушает только 127.0.0.1, работает с `--offline`,
не использует CUDA и не требует разрешения входящих соединений из локальной сети.
Не включены verbose-логи с текстами запросов. JSON-файлы deployment/process и логи
сохраняются в `local_llm/`. Если появится запрос на системные изменения или firewall,
не разрешайте внешний доступ автоматически: передайте текст запроса для проверки.

Проверка `probe_local_llm.py` отправляет только три специально составленных текста,
не CERT. Она проверяет веса, alias сервера, реальный ответ, JSON/Pydantic, точное
evidence, модель в ответе, время и usage. Ошибка даёт ненулевой exit code; fallback
на эвристику запрещён. Обрезанный ответ (`finish_reason=length`) также отклоняется.
В `output/local_llm_probe.json` сохраняются измеренные результаты и provenance.
Это smoke test, не независимая оценка стойкости к prompt injection или качества разметки.

При первой проверке Qwen добавлял пробел в конце `evidence_span`, отсутствующий
в исходном тексте. Сервер возвращал HTTP 200, но проверка точного вхождения цитаты
закономерно отклоняла ответ. При ошибке валидации клиент теперь делает ровно один
повторный запрос к той же модели с инструкцией исправить ответ. Цитаты и оценки
программно не исправляются. Повторный неверный ответ останавливает обработку;
эвристическая подмена запрещена. Сетевые ошибки, несовпадение модели и обрезание
ответа не вызывают такой повтор. В metadata сохраняются `attempts` с usage и
ошибками валидации, хеш инструкции исправления и суммарное время; верхний `usage`
относится к последнему ответу. Исходные тексты в диагностические ошибки не включаются.
При сбое probe сохраняет также `failed_sample` и сообщает конкретную причину.

Остановка именно этого экземпляра:

```powershell
.\scripts\stop_local_llm.ps1
```

PID, путь exe и время создания сверяются, чтобы не завершить чужой процесс.
Автозапуска нет. Скрипты не изменяют и не удаляют исходный CERT.

## После успешного запуска

Для `aam0658` выполнен отдельный полный проход с Qwen и сравнение трёх подходов:
[результаты и команды](aam0658_llm_experiment.md). Специализированный runner сохраняет
проверяемый кэш и использует протокол A без ролевых эталонов; через LLM идут только
629 писем одного сценария. Общая команда `main.py` ниже по-прежнему строит эталоны
и запускает более широкий набор вариантов, поэтому её стоимость отличается.

Перед полным CERT-прогоном нужно измерить время трёх запросов и спланировать объём.
На CPU сотни тысяч сообщений могут потребовать очень длительного расчёта. Даже
режим одного пользователя сейчас строит независимые ролевые эталоны по дополнительным
сообщениям. Не запускайте полный --all-users до оценки скорости и подготовки
возобновляемого извлечения/кэша. В проверке 12.11.2026 три коротких текста заняли
0,86 / 20,94 / 19,67 секунды (1 / 2 / 2 попытки, сервер уже прогрет).
В первом тексте маркеров не обнаружено; во втором и третьем получен
`concealment_intent` с точной цитатой. Эти времена не являются оценкой скорости
на длинных письмах CERT или гарантией качества извлечения.

Полный pipeline уже принимает local_llm и проверяет модель до обработки писем.
Пример **после согласования вычислительного объёма**, не команда обязательного первичного запуска:

```powershell
uv run python main.py --dataset --user aam0658 --semantic-mode local_llm --output output/single_cert_llm
```

Исторические `output/final_cert` и `output/single_cert` содержат эвристические результаты.
Смешивание разных semantic_mode в существующем каталоге запрещено. После завершённого
LLM-прогона генератор статьи принимает `--cert-dir output/cert_local_llm`. Он отдельно
проверяет совпадение provenance датасетного прогона и probe; один запущенный сервер
без повторного LLM-эксперимента не снимает статус «предварительно».
