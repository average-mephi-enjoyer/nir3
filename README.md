# Прототип НИР3

Локальный исследовательский прототип защищённого динамического профилирования.
**Условие приёмки: без реальной локальной LLM эксперимент не принимается.**
Имеющиеся результаты с эвристикой — предварительный контроль, а не итоговый эксперимент.
Развёртывание Qwen внутри проекта: [инструкция](docs/local_llm_setup.md).
Реальный эксперимент `aam0658` завершён: [три подхода, измеренные результаты и воспроизведение](docs/aam0658_llm_experiment.md).
Python 3.13, uv, Pydantic v2. Зависимости закреплены в `uv.lock`.
Исходные CERT и результаты в `output/` не включаются в Git.

## Установка и проверки

```powershell
uv sync --locked
uv run python main.py --help
uv run python -m unittest discover -s tests -v
uv run ruff check .
uv run python scripts/check_source.py
uv run python scripts/validate.py
```

Стандартные тесты синтетические, не требуют CERT, spaCy-модели или LLM.
При наличии `archive/answers/insiders.csv` автоматически выполняется дополнительная
интеграционная проверка структуры разметки; без файлов она явно пропускается.
CI запускает unittest и статический анализ без CERT. Ruff проверяет синтаксические
ошибки, неопределённые имена и опасные конструкции, но не является проверкой типов.

## Полные эксперименты

```powershell
uv run python run_stress_test.py --scenario all --split all
uv run python main.py --dataset --all-users
uv run python scripts/build_publication_results.py
```

Первая команда подбирает параметры только на `tune`, фиксирует их, затем запускает
независимый `test`. По умолчанию 30 seeds на условие, две отдельные серии A/B и 2000
bootstrap-повторений по seed-кластерам. Полный запуск занимает заметное время и место:
сохраняются все траектории и решения в gzip. Конфигурация — `configs/experiments.json`.
Одиночный исследовательский запуск: `--scenario ramp --split test`; число повторений
можно изменить через `--repetitions`, каталог — через `--output`. Если сохранённого
выбора tune нет, используется явно записанная исходная конфигурация, без подбора на test.

CERT-команда охватывает всех пользователей разметки r4.2 (70 сценариев в локальном
выпуске) и выборку до двух сотрудников каждой из представленных ролей. Один проход
по email.csv формирует признаки всей выбранной когорты. Для одиночного сотрудника:

```powershell
uv run python main.py --dataset --user aam0658 --semantic-mode local_llm --output output/single_cert_llm
```

Требуются `archive/r4.2/email.csv`, месячные `archive/r4.2/LDAP/*.csv`,
`archive/answers/insiders.csv` и подробные файлы `r4.2-1`, `r4.2-2`, `r4.2-3`.
Телеметрия file/device/logon используется при наличии; HTTP в массовом запуске
явно помечен `not_loaded`. Пути задаются `--archive` и `--output`.
Отсутствующий CERT вызывает понятную ошибку и ненулевой код возврата.
Ошибки и неоцениваемые пользователи сохраняются в `status.csv`, а не скрываются.

## Результаты

- `output/final_stress/metrics_all_all.csv`: измеренные результаты, параметры и seeds.
- `output/final_stress/sensitivity_tune.csv`, `selected_parameters.json`: подбор на tune.
- `output/final_stress/aggregate.csv`, `summary_A.md`, `summary_B.md`, `summary_A.png`, `summary_B.png`: автоматически рассчитанные агрегаты и интервалы.
- `output/final_cert/metrics.csv`, `status.csv`, `summary.csv`: CERT, включая отказы оценки.
- В обоих каталогах `manifest.json`: конфигурация, Python, зависимости, хеши исходников и uv.lock.
- `docs/publication_results.md`: автоматически построенные данные для статьи.
- `docs/implementation_report.md`: выполненные пункты и оставшиеся ограничения.

Старые результаты `output/sc1`, `sc2`, `sc3` не используются и не перезаписываются.
Повторный запуск с тем же `--output` заменяет результаты той же конфигурации.

## Интерпретация

Эксперимент A меняет только механизм обновления/заморозки при одинаковых признаках,
инициализации, контексте и детекторе. B отдельно проверяет признаки, роль, контекст
и отключение защитных компонентов. Нулевое загрязнение после ранней заморозки не
означает хорошего мониторинга: рядом публикуются доступность, пропуски сценариев
и число ложных остановок. AP после заморозки условна по доступным scores.

Карантин, якорные ограничения и восстановление после проверки описаны математически
в [методике](docs/experimental_methodology.md). Автоматического восстановления по
истинной метке нет. В CERT решения внешней проверки отсутствуют. Experimental
`--conformal` не даёт доказанной anytime/FPR-гарантии и не используется в основной серии.

По умолчанию CLI требует `local_llm`, проверку файлов модели и работающий локальный сервер;
результаты сохраняются в `output/cert_local_llm`. Режим `--semantic-mode heuristic` доступен
только как явно выбранный контроль; используйте отдельный `--output`. Режим `local_llm` допускает
только loopback-сервер и завершается ошибкой при отказе, без скрытой эвристической
подмены; `disabled` выключает семантические маркеры. Проверка сервера на искусственных
примерах: `uv run python scripts/probe_local_llm.py`. Переписка CERT наружу не отправляется.
Порт portable-сервера — 8081; конфигурация, версия и SHA256 — `configs/local_llm.json`.
После полного LLM-прогона собирайте отчёт через `uv run python scripts/build_publication_results.py --cert-dir output/cert_local_llm`.
Независимой экспертной валидации LLM пока нет; [рубрика](docs/semantic_annotation.md)
отделяет авторские категории от оригинального ILI и описывает необходимую проверку.

В CERT тексты — синтетические ключевые слова. Файловое событие означает копирование
на съёмный носитель согласно документации выпуска, но не доказанную эксфильтрацию.
Результаты нельзя переносить напрямую на реальных сотрудников или использовать как
доказательство виновности. Ограничения и неэффективные режимы входят в отчёт эксперимента.
