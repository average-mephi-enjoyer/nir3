# Прототип НИР3

Python >= 3.13, управление окружением через uv. Файлы pyproject.toml и uv.lock должны входить в репозиторий. Данные CERT и результаты не включаются в Git.

## Установка и запуск

Из корня проекта:

```powershell
uv sync --locked
uv run python main.py --help
uv run python -m unittest discover -s tests -v
uv run python main.py --dataset --user aam0658
uv run python main.py --dataset --all-users
uv run python run_stress_test.py --scenario all --split all
```

Для CERT нужны archive/r4.2/email.csv, LDAP/*.csv, device.csv, file.csv и archive/answers/insiders.csv вместе с каталогами подробной разметки r4.2-1, r4.2-2, r4.2-3. Каталог output создаётся автоматически. Параметры --archive и --output задают пути. --all-users обрабатывает девять исследуемых инсайдеров и пять независимых нормальных сотрудников. Полная обработка CERT существенно дороже модульных тестов.

Основной режим извлечения семантических признаков — лексический fallback. Это не результат Qwen. Загрузка spaCy-модели для данного режима не требуется: признаки местоимений и синтаксической сложности вычисляются лексическими эвристиками. Установка сторонней модели вручную не закрепляет её в uv.lock; uv sync удаляет незадекларированные пакеты. Настоящая LLM и проверка её доказательств относятся к отдельным пунктам 12–15.

## Признаки и временной порядок

- Местоименный маркер: соотношение местоимений первого лица.
- Синтаксический маркер: эвристика длины текста и плотности пунктуации; не синтаксический разбор spaCy.
- Активность: сравнение соседних календарных окон исходящих сообщений, одно письмо учитывается один раз.
- Время ответа: сопоставление входящего и исходящего письма по корреспонденту и нормализованной теме с Re:. Это приближение, не доказанная связь треда. В CERT r4.2 тем нет, поэтому компонент времени ответа недоступен и остаётся постоянным нейтральным значением.
- Социальный маркер: степень связности и отдельная доля внешних связей. Betweenness хранится независимо; центральность рассчитывается без трактовки частоты переписки как расстояния.

Обработка требует хронологического порядка email.csv. Для каждого сотрудника отдельно строится граф его наблюдавшихся коммуникаций. Состав графа целевого сотрудника не меняется из-за завершения обучения референтной группы. Это не полный граф организации. LDAP выбирается по последнему доступному на момент сообщения месячному снимку. Командная нагрузка учитывает других сотрудников той же роли, исключает анализируемого сотрудника и события с текущей или будущей временной меткой. При недостатке коллег фильтр отключается.

## Разделение данных

От первого пригодного письма датасета отсчитываются 30 суток обучения, затем 30 суток калибровки и 14 суток выдержки. Наблюдения за 14 суток выдержки продолжают участвовать в контроле риска карантинного горизонта; только созревшие до теста кандидаты попадают в калибровку. Тестирование начинается после этих периодов. Сценарии, пересекающие обучение или калибровку, отклоняются. Параметры не подбираются на тестовом периоде.

Ролевые средние и дисперсии оцениваются по первым пяти доступным нормальным сотрудникам исходной роли в период обучения. Целевой сотрудник, размеченные инсайдеры и пять контрольных сотрудников исключаются из референтной группы. Ролевой prior фиксируется на обучении; автоматическая переоценка prior при смене роли не выполняется. Холодный старт без независимого обучения или измеренного ролевого prior отклоняется; смешанная дисперсия включает различие средних.

Калибровочные значения проходят календарный карантин и допускаются по риску на всём наблюдаемом горизонте. Текущая тестируемая оценка не включается в калибровку. Во время теста калибровочная выборка фиксирована.

## Разметка и метрики

cert_ground_truth.csv содержит начало и конец каждого из девяти сценариев, первое техническое событие, его тип, идентификатор и источник. Первое техническое событие — самое раннее событие file/device/http/logon данного пользователя в подробном answer key. Оно не обязательно означает эксфильтрацию. Начало сценария не объявляется доказанным началом скрытой атаки.

Положительная метка письма означает присутствие его идентификатора среди наблюдаемых событий сценария для целевого отправителя. Это оценка обнаружения размеченных событий, не экспертная оценка злонамеренности каждого текста. Неразмеченные письма внутри интервала сценария имеют неизвестную метку (-1) и исключаются из PR-метрик. За пределами интервала используется отрицательная метка согласно доступной разметке CERT.

Сравниваются Static, EMA, EMA clipped, EMA quarantine и Protected. Для них используются одинаковые потоки признаков, обучающие периоды и правило регистрации новых эпизодов тревоги. Protected дополнительно использует ролевой prior, командный контекст, контроль исторического якоря и заморозку. Значения порогов оцениваются по отдельной допущенной калибровке.

- PR-AP — ступенчатый интеграл precision-recall (average precision), с одновременной обработкой равных оценок.
- Recall@1%FPR — описательная тестовая ROC-метрика; не обещание рабочего FPR.
- Загрязнение — доля размеченных аномальных тестовых наблюдений, когда-либо допущенных к обновлению. Откат не стирает факт допущенного загрязнения.
- Смещение эталона — RMS отклонение итогового среднего от исходного якоря в единицах исходного стандартного отклонения.
- FA/1000 normal user-days — число начал эпизодов ложных тревог на 1000 наблюдавшихся нормальных пользователь-дней. Все календарные дни, пересекающие интервал сценария, исключены и из экспозиции, и из подсчёта ложных тревог. Отсутствовавшие в наблюдениях дни не добавляются в знаменатель.
- Задержка — время от начала сценария до первой тревоги в его интервале.
- Упреждение — время от этой тревоги до первого размеченного технического действия; может быть отрицательным.
- Неопределённые метрики представлены N/A в Markdown и NaN в CSV, без подстановки условных значений.

events.csv сохраняет оценки, метки, тревоги и траектории эталонов. admissions.csv сохраняет ID события, допуск, отказ и отзыв допуска. Совпадение времени и вектора признаков не используется как идентификатор события. metrics.csv содержит агрегаты. Старые результаты в output/sc1, sc2, sc3 не перезаписываются и не считаются результатами исправленной версии.

## Защищённый профиль и последовательное решение

Карантин использует календарный срок и максимум нормированного риска по наблюдениям горизонта. Сохраняется причина каждого решения. Эталон ограничен доверенным историческим якорем по накопленному сдвигу среднего и росту дисперсии. Локальное и историческое отклонения рассчитываются раздельно.

При пороговой тревоге профиль переходит в FROZEN, обновления прекращаются, недавние обновления откатываются, подозрительные кандидаты исключаются. Возобновление требует явного решения после проверки и новой чистой обучающей выборки. Программный интерфейс не определяет достоверность такой проверки автоматически.

По умолчанию используется эмпирическое правило 3 из 5. --conformal включает экспериментальный последовательный показатель. Для адаптивных зависимых данных условная валидность e-values и гарантия Вилле не доказаны. Название совместимого класса ConformalMartingaleDetector не является утверждением такой гарантии. plot_martingale_csc0217.py использует исправленный общий конвейер.

Техническая верификация сохраняет исторические события и выбирает только интервал до тревоги включительно. Интерпретация файловых операций и семантико-технического рассогласования остаётся предметом пунктов 16–17; эти компоненты не использованы как подтверждение эксфильтрации в новых метриках.

## Стресс-сценарии

Отдельный числовой эксперимент проверяет механизм профилирования, не качество LLM: медленный дрейф, скачок, загрязнение относительно адаптирующегося EMA-прокси, доброкачественная смена роли, коллективная перегрузка, индивидуальный стресс и нормальное поведение. Проверяются длительности 30/90 суток, интенсивности 1/3/6 стандартных отклонений. Командный контекст рассчитывается штатным фильтром по синтетической активности коллег; вклад целевого сотрудника исключается. Истинная разметка не передаётся алгоритму обновления.

Раздел tune использует seeds 11/12, test — 21/22. Обучение, калибровка, выдержка и тест разделены по времени. Синтетический ролевой prior получен на отдельной выборке. Файлы для каждого сценария содержат реальные траектории и метрики. Автоматического подбора параметров по итоговому тесту нет.
